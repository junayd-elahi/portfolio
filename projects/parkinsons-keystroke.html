Keystroke Dynamics to Detect Parkinson's

Can the rhythm of someone's typing separate people with Parkinson's from controls? My final-year project tested that claim with evaluation that stops a model from recognising individuals instead of the disease.

The short version~20 sec read
Problem

Many keystroke studies on Parkinson's report high accuracy, but they split data by keystroke or window, so the same person appears in both training and test sets.

What I did

Engineered 51 per-user timing features and evaluated Random Forest and XGBoost with nested, subject-wise GroupKFold against a majority-class baseline.

Result

Neither model reliably beat the baseline. Previously reported results on this dataset don't generalise once leakage is removed, and that negative result is the contribution.

On this page

    01Why this matters

    If samples from the same person land in both training and test sets, a model can learn to recognise individuals rather than the disease, and the reported accuracy goes up for the wrong reason.

    This project evaluates the same problem with subject-wise splits, so every participant appears in exactly one fold, and measures how much of the earlier signal was leakage.

    02Data & features

    Keystroke logs and metadata are parsed and cleaned, physiologically implausible timings are filtered out, and only users with at least 2,000 keystrokes are kept. Each remaining user gets 51 features across hold time, latency and flight time:

    • Central tendency, plus variability: std, skew, kurtosis, IQR, CV, MAD and burstiness
    • Hand asymmetry
    • Directional statistics for left/right transitions (LL, LR, RL, RR)

    Hold time is how long a key stays down. Flight time is the gap between releasing one key and pressing the next. Latency is press to press. Pauses over 2 seconds are ignored, much like the cleaning step filtered out implausible timings.

    04Evaluation design

    • Nested GroupKFold: 5 outer folds and 3 inner folds, grouped by user_id, so tuning and testing never share a participant.
    • Random Forest and XGBoost, each tuned with GridSearchCV on the inner folds, optimising F1.
    • A majority-class baseline as the honest reference point.

    05Robustness checks

    To make sure the negative result wasn't an artefact of one choice, I added three further experiments:

    • Feature-group ablation: central-tendency vs variability vs combined feature sets.
    • Feature stability: which features are repeatedly selected across folds, then retraining on those subsets.
    • SMOTE: oversampling the minority class, to test whether class imbalance explains the result.

    06Result

    Under leakage-resistant evaluation, neither Random Forest nor XGBoost reliably separates Parkinson's from control above a majority-class baseline.

    That's the finding I set out to test. It's a reproducible benchmark showing that earlier results on this dataset don't hold once the same participant is kept out of both sides of the split.
